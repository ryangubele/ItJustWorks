# 使用 It Just Works™

## 它做什么

Skyrim 用 *场景* 处理对话、过场动画和其他带脚本的片段。有时场景永远不会结束。这会悄无声息地挡住后续场景——任务卡住不动，没有报错，也不崩溃。本模组会监视你当前所处的场景，如果你在其中停留了一段时间就提醒你，让你看清它是什么，并在它卡住时允许你停止它。

**简而言之：** 保持默认设置，继续游戏。如果收到提醒，打开 **模组配置菜单 > It Just Works**。

它不修改其他模组的记录，也不需要补丁，因此它在读取顺序中相对于你的内容模组的位置无关紧要。除非你让它停止，否则它不会更改任何场景。

需要 **[SKSE64](https://skse.silverlock.org/)**、**[MCM Helper](https://www.nexusmods.com/skyrimspecialedition/mods/53000)**、**[powerofthree's Papyrus Extender](https://www.nexusmods.com/skyrimspecialedition/mods/22854)** 以及 **[powerofthree's Tweaks](https://www.nexusmods.com/skyrimspecialedition/mods/51073)**（若希望显示名称而非 ID 数字，请设置 `Load EditorIDs = true`）。安装说明见 [模组页面](https://www.nexusmods.com/skyrimspecialedition/mods/185927)。

菜单共五页：**场景**、**监视器**、**设置**、**诊断**、**卸载**。

## 场景

### 你当前所处

当前场景的读数，或者 **无**（未处于任何场景）。菜单在打开时会刷新。

- **场景中的时间** - 你在本场景、本次游戏会话中大致停留的时间（实时）。
- **场景** - 有名称时显示名称；否则显示 ID 数字。
- **Form ID** - 原始 ID，始终显示。便于在控制台中使用，或写进错误报告。
- **所属任务** - 该场景所属的任务。

### 停止场景

如果你认为场景卡住了，这会结束它。

1. 按一次 **停止场景** - 一行文字会确认已预备就绪。
2. 再按一次可取消，或关闭菜单以执行停止。

只停止你认为已卡住的场景。停止一个正常运行的场景可能会破坏东西。停止一个卡住的场景（偶尔）可能会在游戏“追赶”进度时，短暂触发一连串延迟事件。

**刷新** 会在不关闭菜单的情况下重新读取当前场景。在原版 Skyrim 中，由于游戏在菜单中会暂停，刷新未必有用。如果你在使用像 [Souls](https://www.nexusmods.com/skyrimspecialedition/mods/27859) 这样的取消暂停模组，它能让你在不重新打开菜单的情况下刷新。

### 最近的场景

最近十个场景，最新的排在最前，附带大致时长。

## 监视器

替你盯着，你就不用自己盯了。

- **多久后提醒** - 一个场景可以运行多久才会触发提醒。默认 **6** 分钟。**0** = 从不提醒。  
  游戏本身没有任何机制标记场景已卡住，也没有任何机制告诉我们一个场景应该运行多久。所以我们设定一个阈值，超过就提醒你。我们会以一种方式混合游戏时间与实际时间，希望它大致代表“实际花在游玩上的时间”，让这项设置更直观。
- **检查间隔** - 每次检查之间的秒数。默认 **30**。**0** = 关闭监视器。
- **重复提醒** - 默认关闭，因此每个场景只提醒一次。开启后，只要仍超过阈值，就会持续提醒。
- **重复间隔** - 提醒之间的分钟数，仅在开启重复提醒时使用。默认 **5**。

提醒是角落里出现的两行文字，例如：

> 场景阻塞其他场景 ~6m  
> See? It Just Works!

默认每个场景提醒一次，直到你离开该场景或场景发生变化。错过了？打开菜单——读数仍会显示你所在的场景以及已停留多久。模组不会替你停止场景；如需停止，请使用场景页面上的停止场景。

无论你的菜单是否会暂停游戏世界——原版会暂停，像 [Souls](https://www.nexusmods.com/skyrimspecialedition/mods/27859) 这样的取消暂停配置则不会——监视器的行为都一样：提醒始终只是意味着该场景已经运行了一段时间。

## 设置

- **启用** - 默认开启。关闭即可搁置模组而无需卸载。
- **轻松语气** - 默认开启。通知会保持轻松的语气；关闭后改为朴素的措辞。只改变文字，从不改变模组的运作方式。
- **通知语言** - 模组自身角落通知所使用的语言。当你选择默认菜单语言时，安装器可以为其设定初始值；你也可以随时在本页更改。默认并回退为英语；与游戏本身的语言设置无关。
- **显示当前场景名称** - 绑定一个按键；按下即可在不打开菜单的情况下查看当前场景的名称。
- **清除热键** - 移除该按键绑定。
- **诊断日志** - 写入 Papyrus 日志的详细程度。正常游玩时保持 **关闭**。提交错误报告时使用 **事件**；只有在追查时序问题时才使用 **每次检查**，用完记得改回关闭。可能影响性能，尤其是在 **每次检查** 时。

  日志记录仅在游戏本身正在写入 Papyrus 日志时才有效。在 `Documents\My Games\Skyrim Special Edition\` 中，编辑 `Skyrim.ini` 或 `SkyrimCustom.ini`：

  ```
  [Papyrus]
  bEnableLogging=1
  bEnableTrace=1
  ```

  重启游戏。日志文件：`Documents\My Games\Skyrim Special Edition\Logs\Script\Papyrus.0.log`。搜索 `fth_IJW`。

## 诊断

- **已加载 Editor ID** - 一个指示灯。点亮时，场景页面上的场景名称与所属任务会显示名称；熄灭时则显示 ID 数字。无论哪种情况，Form ID 始终显示原始的 `0x…`。

- **监视器** - 后台检查是否在运行：
  - **运行中** - 正常
  - **唤醒中** - 重新加载后片刻属于正常
  - **延迟** - 仍在工作，只是检查比平时慢（游戏繁忙）
  - **关闭（检查已停用）** - 你将检查间隔设为了 0
  - **休眠（已关闭）** - 设置页面上的启用已关闭

- **最近一次自我修复** - 模组有时会修正自身的记录（通常发生在重新加载之后）。此处出现一行文字属于正常现象。

## 疑难解答

### 场景显示为 ID 数字而非名称

po3 Tweaks 没有加载 Editor ID。在 `po3_Tweaks.ini` 中设置 `Load EditorIDs = true` 并重启 Skyrim；诊断页面的 **已加载 Editor ID** 指示灯可以确认这一点。模组管理器可能在部署或更新时覆盖该文件，因此请编辑 Tweaks 模组*内部*的那份副本（或一个能胜出的小型覆盖模组），而不只是 `Data` 里的散装文件：

- **MO2：** 左侧面板中的 Tweaks 模组文件夹，或 Overwrite／更高优先级的模组。
- **Vortex：** Tweaks 的暂存文件夹，或一个覆盖模组。每次更新后请重新检查。

无论哪种情况，Form ID 都会显示，所以你永远不会完全摸黑。

### 通知语言不对

角落通知遵循 **设置 > 通知语言**，而不是游戏语言，也与安装了哪个菜单翻译文件无关。英语是默认值，也是回退值。

正常运行安装器并设置默认菜单语言时，也会为该设置项写入初始值，使菜单与通知保持一致。如果你只是手动替换了菜单文件，或在升级时没有重新执行该安装器步骤，请手动将通知语言设置一次，使其与菜单相匹配。

### 菜单语言不对

MCM 菜单遵循游戏本身的语言设置，而不是上文的通知语言。Skyrim 会加载与游戏语言相匹配的翻译文件，因此即使你安装了其他语言，英文游戏仍会显示英文菜单。有两种方式可以更改：

- **安装器：** 在第 1 步勾选你的语言，然后在第 2 步将其选为默认菜单语言。这会覆盖英文菜单文件（并保留一份英文 `.bak`），**并且** 会为通知语言写入匹配的初始值。
- **手动：** 将 `Interface\Translations\fth_ItJustWorks_<LANGUAGE>.txt` 重命名为 `fth_ItJustWorks_ENGLISH.txt`，替换英文文件。这**不会**更改通知语言——请在设置页面手动将其设为匹配，否则通知仍会是英语。

### 菜单或通知显示为乱码或无法辨认的字符

文字本身没有问题——只是你的游戏没有能绘制这些字符的字体，于是显示成乱码。Skyrim 的原版字体覆盖拉丁字母和西欧字母，但不包含西里尔字母、中文、日文，或某些中欧文字符号。如果你在其中一种语言下使用菜单或通知，请安装一个包含这些字符的字体模组；大多数非英语配置通常已经安装了一个。如果你的没有，可以在 Nexus 上搜索覆盖你所用语言的字体——[Unicode Font](https://www.nexusmods.com/skyrimspecialedition/mods/103346) 是一个不错的起点。

### 从不出现任何提醒

先查看诊断页面上的监视器状态，再检查监视器的各项设置：

- 状态 **休眠（已关闭）** - 模组已关闭。在设置页面打开启用。
- 状态 **关闭（检查已停用）** - 检查间隔为 0。将其设回 10-240 秒。
- 多久后提醒 为 **0** - 这会禁用提醒。设置你想要的分钟数。

提醒所使用的时间计算方式与多久后提醒相同，因此场景中的时间偶尔会显示得很高却没有触发提醒——这是正常现象。它是实际时间，会在重新加载时重置。即使没有通知，菜单也始终会显示当前场景以及你在其中停留了多久。

### 停止场景没有清除场景

在 10 多年解卡存档的经历中——先是用粗糙的一次性版本，如今是用这个模组——停止操作从未失败过一次。所以如果它真的报告说场景没有结束，那么你要么发现了模组里的一个 bug，要么遇到了某种全新的情况。这令人兴奋。惊讶正是学习发生的地方。一份完整的日志是查明原因的最佳机会。打开 Papyrus 日志记录，将诊断日志设为 **每次检查**，并打开你整个加载顺序中能找到的每一个日志或调试选项，这样如果它再次发生，就能被记录下来。然后把完整的 `Papyrus.0.log` 作为错误报告发送。同时，从卡住之前的存档重新加载，以便在此期间继续游戏。

### 提交错误报告，或寻求帮助

报告 bug 时，将诊断日志设为 **事件**，重现问题，然后退出游戏。在开启 Papyrus 日志记录的情况下（`Skyrim.ini` 的相关设置说明见设置页面），打开 `Documents\My Games\Skyrim Special Edition\Logs\Script\Papyrus.0.log` 并搜索 `fth_IJW`。请附上该日志、场景的 Form ID 与所属任务，以及卡住时你正在做什么。

发送到哪里：

- **错误报告：** 模组页面的 [Bugs tab](https://www.nexusmods.com/skyrimspecialedition/mods/185927?tab=bugs)，或 [GitHub Issues](https://github.com/ryangubele/ItJustWorks/issues)。
- **提问与一般帮助：** 模组页面的 [Posts tab](https://www.nexusmods.com/skyrimspecialedition/mods/185927?tab=posts)。

## 卸载

**彻底移除：**

1. 在设置页面，关闭启用。
2. 存档，退出到桌面。
3. 在你的模组管理器中移除该模组（或手动移除）。

可以在游戏进行中途安全移除。与其他带脚本的模组一样，Skyrim 可能会在存档中留下一小段无害的脚本残留；游戏会忽略它。可选：存档清理工具（例如 FallrimTools 中的 **[ReSaver](https://www.nexusmods.com/skyrimspecialedition/mods/5031)**）可以在移除后清理这些残留——请谨慎使用清理工具，只针对你确实打算移除的内容操作。清理*其他*模组的残留时，你可以让本模组保持安装状态。
